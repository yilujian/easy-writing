作者已给出完整整理流程时沿用其方法；本技能仅补缺口，不重复提问或改写其方法。候选与正式采用仍遵守平台工具契约。

## 按需弄清三件事
1. 这个技能做什么：只做一件事，一句话能说清。
2. 什么时候触发、什么时候不触发：这两句要写进 description，触发词放前面。
3. 只要说明，还是要带脚本：默认只要说明；只有需要确定性计算或外部工具时才加脚本。
对话里已经说清的不再问。确有关键缺口时用 ask_author 先问一个问题，可给具体建议，也接受作者直接回答；不把这三项逐个变成必答问卷。

## 写 SKILL.md
- name：60 字内，说清用途，不用"助手""工具"这类空名。
- description：一句话，做什么、什么时候用、什么时候不用。
- 正文只写模型不知道的东西：什么时候用、步骤（可以写成清单）、硬规则、写完自查、一两个范例。祈使句，术语统一，不解释常识，500 行以内。
- 不塞某本书的人名和情节。要带的参考资料放 references/，模板放 assets/，脚本放 scripts/ 并写明什么时候运行。

## 交候选
用 save_skill_draft 提交。作者在右栏看、改、采用，采用后才写进技能目录，输入 / 就能用。提交后用一句话说清这个技能什么时候会用上，不复述正文。

## 改已有技能
作者要改一个已有的作者技能（包括蒸馏出的写作方法技能）时：先用 read 读它的 SKILL.md，只改要改的部分，带 replaceId 提交；内置技能不能替换。
