## 执行规则

- 以用户指定的《Agent板块最新版方案.md》为阶段依据，以当前代码为实现事实。

## 第 2 步：开发前确认（2026-10-30）

状态：用户要求开始第二步，并明确要求先确认根因和修改逻辑。本轮只核对代码、整理范围和更新记录，尚未修改功能代码。

已核对的根因：

- `pi_creation.rs::positioning_question` 仅检查读者、分类、平台字段是否 unknown，不检查是否已有故事想法，固定给出“根据我的故事推荐／暂不限定”。
- `preflight` 把建书任务、修订、决定登记作为查榜和候选提交的前提；分类未确定时先出卡，导致本来可用于发现题材的榜单资料无法参与推荐。模型承担抄写来源、维护状态与交付清单的额外工作。
- `PiCreationRecord.vue` 在聊天内容之前展示任务台账，未明确字段和待回答问题重复占据空间。
- `research-tools.ts::readRankings` 的筛选主要针对榜单来源；起点、七猫的“全分类”来源可通过分类匹配，但榜内条目未继续按分类筛选。缺少方案要求的番茄频道分类概览、过期数据确认及同会话去重。
- 内置建书 Skill 同时要求维护台账，并仍写有第一步已移除的简介截断、nextIntroOffset 续读规则；方法说明与现有接口不一致。

拟确认范围（未执行）：

1. 删除独立的建书记录工具、固定定位卡和顶部台账面板，撤掉“先登记建书任务才允许查榜/提交”的流程依赖。问答原文、选项和时间沿用现有 Pi 会话记录，由平台登记；模型理解自由回答，不承担抄原句、填状态和传任务号。保留作品归属、候选修订与正式采用校验。
2. 重写内置建书 Skill：按已有信息进入；无故事时给具体可选方向或只补必要定位，有想法时围绕该想法推荐，已明确的信息不再问，局部起名/简介不扩展为完整开书。同步现有合并接口与完整本地简介规则，不改作者自定义 Skill 原文件。
3. 按方案补齐榜单查询：平台/频道未定时只提供可用范围和缓存日期供选择；分类未定但平台/频道已明确时，番茄按该频道各分类前 5 名合成探索概览，起点/七猫读该频道总榜；分类已定则按相应来源或条目分类筛选。跨平台/频道探索须有作者明确选择或委托，不默认读全部榜单。
4. 旧快照或无缓存时，由平台确认“刷新相关榜／使用现有资料或继续讨论”，同会话同来源不重复追问；刷新后接着原任务继续。沿用现有爬虫、榜单开关和半小时内缓存规则，不新增作品页抓取、不自动刷新全站。
5. 常见完整开书路径为“必要定位 → 相关榜单 → 具体故事方向 → 书名简介 → 可编辑候选 → 作者采用”。这些是按需进入的环节，不强制三张卡或每次从头走。正式采用后再根据作者原要求决定是否继续写正文。
