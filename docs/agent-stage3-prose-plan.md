# Agent 第三步开发方案｜正文写作与去 AI 味

2026-10-31 · 已确认开工 · 第二步已基本通过真机验收

**本轮交付两项可直接使用的能力。** 作者说“写第十二章”，右栏收到的第一份候选就应读起来自然，接得上前文。作者说“只把这三段改得像人写的”，右栏收到的就是这三段的改稿，人物、事件和线索照原文保留。单章、连写、独立短篇共用同一套正文生成。技术回归和实际文风分别验收。

## 一、作者会怎样使用

| 作者的要求 | 平台如何处理 | 作者最终看到什么 |
| --- | --- | --- |
| “第十二章写陆川追查失踪同事，让第三章那把刀派上用场。” | 取目标章位置、前两章、对应章纲和早先关于刀的原文。结合陆川此时知道的事写这一章。 | 一份第十二章候选，可编辑、可采用。聊天只报完成情况。 |
| “接着写三章，第二章结尾不要揭晓是谁。” | 列出三章各自的目标、预计消耗，确认后逐章生成。上一章采用后，下一章读取作者实际采用的版本。 | 一次看一章。改了上一章，下一章接改后的内容。暂停后从未完成处继续。 |
| “把这三段去掉 AI 味，别动剧情。” | 把指定原文作为改写底稿。前后文用来衔接。作者给了章节和选段时，用章节版本和原文位置确定修改范围。 | 一份局部改稿，附至多三句具体改动说明。采用只替换目标区间，其他正文和格式保留。 |
| “写个三千字短篇，结尾让读者重新理解开头。” | 已有设定就直接写，缺少会改变故事走向的决定才问。短篇一次生成完整候选。 | 预览和编辑整篇。正式采用时一次完成建书、建卷和写首章，同一候选重复采用不会多建书。 |
| “这段是我从别处贴来的，帮我改顺。” | 使用贴入的原文。没有确定对应作品或章节时，以独立文本候选交付。 | 可看、可编辑、可复制。作者另行指定保存目标后才写入作品。 |

只讨论写法、分析问题或要求在聊天里举两句例子时，仍走普通对话。无须每次选文风或填写写作表格。

## 三、一份正文怎样从作者要求变成候选

1. **聊天模型生成简报。** 写明目标作品、章节或原文范围，本章要发生什么，必须保留的事实，应采用的写作方法。对于“上一轮说的不要写内心独白”等要求，简报引用作者消息或选择卡回答的位置，平台取回原话。新要求覆盖旧要求。已撤销的指令、模型自己的建议、书中人物的台词不进入作者要求。仅缺可从作品中读取的资料时由平台补齐。只有目标或授权真的有歧义时才问作者。
2. **平台在写前固定目标。** 记录本次会话、实际绑定的书、章节顺序、原稿版本和已选 Skill 版本。新章沿用已有写作准备流程确定插入位置。改上次的候选时以候选最新修订为底稿。若作者说“只改这段”但同一段文字在章中出现两次，先让作者指定位置。
3. **分别准备文风和故事资料。** 文风说明决定怎样表达。本书资料和作者要求决定本章能发生什么。已知事实和未来章纲分别标明。具体取材规则见下两节。
4. **发起一次独立正文请求。** 使用当前会话选定的同一模型、供应商配置和取消机制，给足正文输出空间。请求只包含写作任务、作者要求、文风和本书资料。让模型在这一次生成里对照范文、人物口吻和事实修整，返回完整终稿。单章或一次改写各对应一次正文请求，连写每章一次。聊天理解和已授权的账本提炼单独记账，记录实际请求数、用量和耗时。
5. **平台交付并等待采用。** 现有候选服务负责写入一份可编辑候选，聊天只返回候选引用和简短回执。生成中止、供应商报错、输出被截断时明确告知状态，不把半稿当终稿。提交和采用均核对目标与版本。迟到的结果不能写进切换后的作品，重复回执不能多交一份稿。

对模型新增两个职责清楚的工具。拟用 `search_chapters` 查本书原文，用 `write_prose` 提交写作简报，对应 Claude 方案的 `chapter.search` 和 `prose.write`。工具参数描述目标和依据，作品身份、版本、模型和保存位置由宿主核实。资料、大纲等候选继续走现有保存能力。作者直接提供定稿或手动编辑时保留原文，避免保存操作反过来改写作者的字句。

实现上，Pi 扩展负责声明工具和接收简报，现有工具桥把请求交给写作服务。按目标章取资料和查证据的逻辑放在已有 Rust 写作服务，正文执行端沿用现有模型调用、取消和记账能力，显式传入会话选中的模型。候选服务持有写入权。正文请求成功后用会话、调用、目标及底稿版本关联候选和材料记录，只保存必要的来源引用。发生断线时先核对是否已交付，再让作者决定是否重试，避免重复付费或双份候选。

## 四、真人感和去 AI 味具体怎么做

**新写正文。** 重写内置基础写作 Skill，用短小的正反例说明该怎样落笔。每次写作结合当前场景和已有角色，重点处理三件事：谁在看，他此时能知道什么；人物为什么在这一刻做这个动作或说这句话；前一句怎样引出下一句。允许旁白、长句和心理描写，节奏由题材、人物和作者要求决定。不要把所有章节改成短句、对话或同一种悬疑腔。

**改已有稿。** 把原文、改写范围和需要保留的细节一起给正文模型。可以删去重复解释，重组句子，恢复人物各自的语气。举例，原文写“他握住了门把，又松开了。他犹豫不决，一时拿不定主意要不要进去。”在上下文已能表现迟疑时，可以留下“他握住门把，又松了手。”不能为了显得生动，多写门内有人咳嗽。这会凭空增加一条可能影响情节的线索。原稿本来顺畅时允许少改。

**文风选择。** 本次明确指定的文风优先，然后是作品默认文风，最后是内置基础写法。作品设置提供一个可选的默认文风，单次使用不会改掉它。作者选的是结构或创作流程 Skill 时，只沿用它负责的部分。成熟文风包按 Claude 方案整理约十条有例子的写法、3 至 5 段范文、少量反例和来源，不要求作者手写的普通 Skill 先凑齐数量才可用。指定 Skill 缺失或被禁用时让作者知道，由作者决定是否改用别的写法。

**新书第一章也要验。** 有已采用且适合代表本书口吻的段落时，优先用作本书范文。有作者提供的样稿时可明确选用。新书既无前文又无自定义 Skill 时，直接用内置说明及其中的原创微型示例写，明确其身份是写法示例。外部范文的人名、物件、世界观和剧情不能成为本书事实。实际效果用盲读检验，不用禁词数量、模型自评分或 AI 检测比例代替。

## 五、长篇取材和旧书补记

| 资料 | 平台怎么取，怎么约束 |
| --- | --- |
| 邻近正文和章纲 | 默认读取目标之前最近两章有正文的正式版本，连同本章对应的大纲段。第一章没有前文就按新书处理。改稿时另带目标原文。未来大纲中计划发生的事标为计划。 |
| 人物、状态、伏笔 | 以目标章之前为界，取相关人物当时的位置、持有物、关系、知情范围及未收伏笔，附出处。改第十章时不能拿书末“当前状态”倒灌给第十章。当前章中已经出场的事实由改写底稿提供。 |
| 远处原文 | 作者点名“第三章那把刀”时先直读第三章，再查后续有无转手。只记得物件或人物时，用简报中的名称查现有索引。在本书、允许的章节范围内排序再截取，返回章号、标题、命中片段和版本。对无命中、缺索引、原文互相矛盾分别处理，不能把推测写成回忆。 |
| 上下文容量 | 按实际模型窗口预留本次正文所需输出。预算紧张先去掉重复命中和次要材料，保住作者原话、修改底稿、关键事实和选定的文风说明与范文。前两章或其他必要原文仍放不下时，说明限制，请作者选择分段或调整范围。不得静默截断作者要求。 |

**旧书补记是单独的可选任务。** 预览需要整理多少章、预计模型用量与耗时。能算费用就显示，缺少单价就只报用量。作者确认后按章推进，沿用账本版本和作者手动更正，支持暂停、失败后从未完成处继续。前章被作者改动时，从失效位置重算。覆盖不完整会标出来，能从正式原文查证的内容仍然可以用于写作。普通续写不会顺带启动整本书的付费整理。

## 六、开发顺序和每步完成条件

| 顺序 | 可检查的交付物 | 通过条件 |
| --- | --- | --- |
| 0 · 先留旧稿 | 固定隔离作品、目标章节、作者要求、模型配置和测试样本，用当前正式 Agent 入口生成旧版样稿。 | 先留稿再动生成逻辑。保留全部样稿和失败，预留未参与调写作方法的题目。 |
| 1 · 文风与资料 | 基础写作 Skill、作品默认文风设置、简报与原话引用、文风和本书资料的独立组装。 | 在测试请求中看得到正确的原话、Skill 版本、范文与本书来源。无样稿的新书也能开始。 |
| 2 · 长篇检索 | 接入本书原文搜索、目标章时点的人物事实和伏笔、老书补记。 | 早章关键细节可找回。其他作品、后文章节和未采用候选不会作为已发生事实进入正文。补记可中断恢复。 |
| 3 · 单章与局部改稿 | 接通一次独立模型调用、候选提交、已有候选修订和原文区间替换，清理并行的旧生文路径。 | 真机从普通对话完成写章和去 AI 味。每次只有一份可编辑候选，未采用时正式正文不变，选段外保持原样。 |
| 4 · 连写与短篇 | 连写逐章调用同一入口。独立短篇在采用时建书并写首章。 | 作者改了上一章，下一章接修改后版本。停止后不偷跑。重复点采用或保存中断不会多建书、遗留半本书。 |
| 5 · 工程回归与成文验收 | 定向测试、全量工程检查、隔离桌面操作、真实模型调用记录、匿名对照稿和失败清单。 | 工程与文风分别记录结论。只有两项写作体验都通过作者验收，第三步才标为完成。 |

## 七、验收怎样判

**工程验收。** 检查普通聊天与开书不误触正文调用，单章、连写、粘贴段落、整章改写和独立短篇都从真实入口交付。主动制造切书、取消后迟到、生成中手改原章、采用前改候选、网络中断和重复采用。关键结果是原书不被错写，局部改写范围外零变化，单章失败不推进下一章。观察实际送给供应商的正文请求，核对模型、作者原话、材料来源与请求次数。通过日志区分“材料确已送达”和“模型在成文里正确使用了它”。

**效果验收建议。** 固定 8 组新旧配对样稿，每组用同模型、相同作者输入、同版本作品资料和相近篇幅，随机隐藏新旧标签。4 组新写覆盖无范文的新书开头、生活对白、跨章伏笔、短篇结尾。4 组改写覆盖重复解释、人物对白、局部改稿、应保留原有叙述节奏的段落。每类预留一组不参与开发调试。作者逐组选择更愿意采用哪份或相当，并指出最想删改的一两处。记录事实错误、人物口吻、阅读是否顺畅和实际手改量。反例与失败稿一并交付，不挑最好的一篇。

建议通过线是新写和改写各有至少 3/4 组新版更愿意采用，两类分别计算。新增关键事实错误、错认人物知情范围、改到指定段落之外或未经采用写入正式作品，都须先修复。8 组只能作为这轮样本验收。若工程通过但成文仍显生硬，记录为“工程通过，文风未通过”。按失败来源分别追查材料没取对、作者要求漏传、范文不适合，还是模型拿到正确材料后仍写差。

## 八、开工范围

按本稿确认后，先执行第 0 项，用真实模型留旧稿。开发记录持续登记每一项的实现、证据和未通过样本。建议你这次一并确认两个产品细节：无绑定的粘贴改稿以独立文本候选交付，以及上述两类分别盲评的通过线。第四步再做从参考书蒸馏新文风 Skill 和仿写，第三步的基础写作、已有文风使用和去 AI 味均独立可验收。
