# 存储升级安全验收

更新日期：2026-10-09。范围：main 工作区的存储升级与损坏正文保护；未提交或发布。

## 已实现

- 启动统一决定模式。失败后重新读取原生完成凭据：提交完成就使用新库；未提交且原数据可读取才继续旧模式。记住旧模式，后续启动不强制重迁。
- 普通资料、词库、工作流、设置、字体、图片和备份都按当前模式读写。正文有 SQLite 时继续 SQLite；最旧的纯 IndexedDB 正文保持原位置。没有运行期换库和长期双写。
- 独立窗口共享原生模式；手动重试先保存并重启。写入失败、生成任务或独立窗口尚未结束时不执行重试。
- 正文解析失败与没有记录分开处理；损坏内容、归属错误不能自动覆盖。编辑器显示持久错误及重新读取按钮，禁用标题、正文编辑和保存。
- 参考资料比较原值后原子提交，防止另一窗口用旧副本覆盖新改动。
- 旧模式备份读取旧数据。恢复使用现有原生事务，同时安装需要保留的旧内容、备份内容与模式完成记录；旧源保留。结果不确定时暂停写入直到重启确认。

## 自动故障验证

- 前端：暂存半途失败进入旧模式；失败后继续写入；重启不再次迁移；手动重试迁入最新词条和设置；提交回复丢失仍选择新库；无法读取数据库时不创建替代库。
- 真实 SQLite：非法 JSON、null、空对象、正文类型错误、章节归属错误拒绝读取和覆盖；写入失败保留上一版；合法空稿仍能保存；损坏书籍不从列表/导出中静默消失。
- 旧模式的全量 ZIP 导出/合并恢复包含失败后新增的参考资料、字体及设置，不包含启动偏好。
- Rust 子进程在“暂存中”“事务未提交”“提交后未返回”被 kill，随后重新打开真实 SQLite；核对原内容、完成状态和继续写作后的重试结果。
- 原生恢复失败回滚数据库和提示词；旧模式恢复与完成标记一起提交；重复恢复后状态仍可正常启动。
- 模式改变和恢复时的维护屏障会等待旧写入；未保存失败不能被忽略。

验证结果：`pnpm check` 的类型检查、Lint 与 370 项测试通过，1 项跳过；Rust 49 项通过，1 项真实网络测试默认忽略。macOS 调试应用构建通过。生产前端构建通过。

原生子进程强制终止、回执丢失、恢复事务与多窗口旧值覆盖均使用测试目录，没有对用户正文做故障注入。

## macOS 原生验收

使用独立的 `易创存储验收.app`，标识 `com.yichuang.writing.storage-safety-test`。正文与 WebView 存储均在该标识的测试目录；测试备份写入 `/tmp/ew-storage-safety-backups`。不修改正式 `com.yichuang.writing` 数据。

1. 使用旧格式 SQLite 样本，注入一个无法迁移的封面数据，触发真实迁移异常。
2. 应用仍进入工作台，显示“已继续使用原有数据”；原稿可读。
3. 补写正文、新增常用词条，保存成功。一键 ZIP 备份包含补写正文和新增词条；此时统一资料表仍为 0 行。
4. 完全退出并重开，迁移 runId 未变化，保留旧模式。
5. 关闭应用，仅移除测试封面故障，再从“保存与备份”点击“重试数据升级”。
6. 应用重启后迁移完成。数据库核对补写正文逐字不变，新增词条进入统一资料表；界面仍显示正确正文、词条，并能继续新增词条。
7. 单独注入损坏正文，初次确认报错且原记录未被覆盖；发现空白编辑区和“云端保存失败”文案不够明确，已改成持久错误提示、禁用编辑/保存和重新读取入口。解锁后完成最终复验：标题和保存按钮禁用，正文编辑区隐藏，显示“正文读取失败”；点击重新读取并按保存快捷键后，SQLite 中的损坏原记录仍逐字不变。
8. 完全退出后恢复隔离样本原稿，重开确认标题、正文和词条完整，编辑与保存恢复可用。实际输入测试文字后撤销并保存，数据库再次核对正文与原样本一致，最终关闭验收应用。

截图位于 `docs/design/storage-safety/`：`legacy-mode.png` 为旧模式入口，`migrated-writing.png` 为迁移后的正文和词条，`corrupt-draft-blocked.png` 为最终损坏正文保护，`recovered-writing.png` 为恢复后的正常编辑。截图和构建产物均不进入应用资源。

前半段验收的提示词目录是既有共享路径，只读加载及导出，没有执行提示词修改或原生恢复覆盖；验收前后 18 个文件的 SHA-256 一致。后续目录读取发生等待，采样确认同步文件 I/O 阻塞主线程，已将启动提示词读取与缺省文件创建调度到后台线程。

最后的错误界面复验使用 `/tmp/ew-storage-isolated-build-20261008` 中的源码副本，只替换提示词目录到独立临时目录，其余代码和前端产物一致，构建与界面验收均已通过；此测试专用路径没有进入仓库代码。原生恢复的文件回滚测试也使用独立临时目录。

## 边界

- macOS 实机验收已覆盖迁移失败后继续写作、持久旧模式、一键备份、手动重试、新模式保存、损坏正文阻止覆盖，以及恢复后重新编辑。Windows 已在 Parallels 的 Windows 11 ARM64 上运行 x64 安装包完成升级与恢复验收，详见 `docs/windows-storage-verification.md`；不等同于原生 Intel/AMD Windows 硬件及所有 Windows 版本的覆盖。
- 强制终止子进程验证了进程中断恢复，不等同于断电、磁盘物理损坏或所有硬件故障。
- 原数据本身不可读取或提交状态不明确时，仍停止写入；不能以提高可用性为由猜测数据源或创建空库替代。

## Windows 追加修复

Windows 验收发现旧数据中的非法封面 Data URL 可以进入备份，却在恢复编码时中断。备份与恢复现在使用同一个图片数据解析器：仅在传输副本中跳过无法解析的封面并报告警告，保留原数据库或原 ZIP；正文、角色与历史继续处理。覆盖导入使用独立的封面编码入口，防止当前界面缓存的坏封面引用被重新写回。新增 4 项回归测试，并用修正后的 Windows 安装包恢复此前生成的坏封面备份，正文、排版、标题、参考资料与历史均核对通过。
