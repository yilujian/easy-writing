# Agent Pi 首阶段开发计划

更新日期：2026-10-21。

本计划用于继续开发独立的 **Agent(Pi版本)**。首阶段交付目标为：基于完整 Pi 底座，在已有作品中完成“读资料 → 写新章节或修改章节 → 预览及编辑候选稿 → 作者确认保存”的闭环。

当前状态：前四批基础实现后，已按用户确认的第一阶段连续完成真实 DeepSeek Flash/Pro 联调、最新正文读取约束、长资料/会话压缩验证、备份恢复联动、必要清理和可重复验证入口。开发及技术验证完成，文风效果供作者结合样稿确认。见 [实现进展](../agent-pi/README.md)。第二阶段平台创作能力扩展现已获授权并在实施；交付准备仍属第三阶段，旧 Agent 会话迁移不安排。

## 1. 已确认的范围与行为

| 编号 | 要求 |
| --- | --- |
| R1 | 使用完整 Pi 实现二次开发，尽量沿用其执行、会话、事件、取消和上下文机制，避免另建通用 Agent 引擎。 |
| R2 | 只在独立 Agent(Pi版本) 中开发。旧 Agent 只复用界面样式，不将其任务编排迁入新版；保留原入口和代码。 |
| R3 | 不改变妙笔、续写、扩写、润色等原有功能及模型配置行为；共享平台数据能力按实际接口复用。 |
| R4 | 读取绑定作品的信息、目录、正文及必要的既有人物、大纲和设定资料。目标或创作要求存在关键歧义时先询问作者。 |
| R5 | 支持修改既有章节，也支持在已有作品中生成新章节候选；新章节只在作者确认保存时创建。按作者指令确定已有卷，默认追加卷末；归属不明确先询问，保存前展示目标。 |
| R6 | 候选稿可预览、编辑。确认保存提交作者确认的内容，不再调用模型重新生成。 |
| R7 | 正式写入保护人工修改，保留既有章节的原文历史；重复确认、重试或回执丢失不得造成重复写入或重复建章。已由作者确认的正式保存独立完成，不受模型停止信号中断；明确失败时整体回滚，结果未知时先查询。 |
| R8 | 要求写一章时只处理本次授权章节，不自动追加下一章。停止取消生成和工具操作，状态反映实际结果。正常对话保持 Pi 进程；主动停止后关闭该实例，下次发送恢复同一会话，不自动重放旧任务。 |
| R9 | 切换到书库、编辑器等其他页面后，任务继续；返回 Agent 页面时能看到实际进度和结果。 |
| R10 | 基础会话与草稿持久化、重新进入后的回读属于闭环要求。Pi 运行时关闭主窗口需提示确认，停止并完成必要保存后关闭；已落盘会话/草稿保留，彻底退出后不自动续跑。保存收尾不代表自动采用候选正文。 |
| R11 | 暂不替换旧 Agent，不打包发布。新建作品、人物/设定管理、拆书、榜单、自动连载等其他业务逐项确认后另行安排。 |

现有 Pi 大纲候选等超出本次重点的实现先保留；本计划不授权删除、重做或扩展这些功能。既有未提交修改也不作为本次清理对象。

## 4. 架构与契约评审必须解决的问题

1. **运行状态与责任归属。** Pi 负责模型执行生命周期；宿主负责进程与通信状态；平台负责草稿及正式保存结果；界面负责展示和交互状态。必要的界面状态不是第二套执行引擎，但不能独立推断模型已完成。
2. **运行结束的语义。** 对照锁定版本的 Pi RPC：命令接受、一次底层执行结束和整体安定不是同一事件。前端恢复同步、重试和停止显示必须有明确依据，不能只看一次响应或流式输出是否结束。
3. **切页持续执行。** 平台工具与事件接收不能因 Agent 页面卸载而失效。先检查现有应用级存活机制，再选择最小调整；不为此自动引入另一套调度器或队列。
4. **候选稿与正式写入。** 设计既有章节修改和新章节候选两条分支。新章节正式创建、正文保存、目录元数据和采用回执需要定义一致性边界；重复请求与进程重启后的重试必须能够识别同一次采用。
5. **版本与冲突。** 明确候选版本、目标章节版本和作者确认的对应关系；确认后继续编辑候选、编辑器同时修改正文、目标被删除等情况不能静默覆盖。
6. **取消、超时与迟到结果。** 区分取消模型、取消未提交的工具操作和已经提交的保存。取消接口返回或 HTTP 断开不自动证明业务副作用已撤销；超时也不等于服务器没有执行。明确提交边界与回读方法。
7. **会话、上下文与模型。** 会话历史沿用 Pi；作品资料按任务需要读取，评审长资料与长历史的处理。模型配置读取不得改变原有功能的默认模型。新需求如运行中换模型、并行任务，先确认范围。
8. **恢复与上游维护。** 明确重进页面、应用重启、进程异常退出的区别；上游版本与本地补丁可追踪。会话纳入全量备份不因基础持久化已经存在就视为完成。

以上是 G2 时点的设计审查项；后续实现与验证状态以开发说明和执行记录为准，不能用这段历史记录替代当前验收结果。

## 6. 首阶段验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A1 | 绑定已有作品，读取目录、章节和参考资料 | 数据属于正确作品；缺失或不明确的目标不会靠猜测写入 |
| A2 | 要求修改已有章节 | 生成候选；确认前正文、章名和历史保持原状 |
| A3 | 要求写一个新章节 | 先形成候选；确认前目录不增加正式章节；确认后创建一个目标章节并保存相应正文 |
| A4 | 作者编辑候选后确认 | 保存作者确认的内容；确认操作不产生新的模型生成请求 |
| A5 | 连续点击、并发确认、回执丢失后重试 | 同一次采用只产生一次有效结果；新章节不重复创建，历史不无故增加 |
| A6 | 编辑器修改原文后采用旧候选 | 明确报告冲突，保留作者内容及可查看的候选，不静默覆盖 |
| A7 | 在模型输出、工具等待、候选写入边界点击停止 | 不显示虚假完成、不自动续写；完成停止后旧实例不能再提交候选并已退出；已确认的正式保存独立完成；下次用户发送才恢复同一会话 |
| A8 | 切换到书库或编辑器，再返回 Agent | 任务继续；进度与结果可恢复展示；不重复启动任务、丢失工具回执或重复写入 |
| A9 | 模型失败、通信超时、Pi 意外退出、保存部分步骤失败 | 明确区分已知失败与结果待确认；不会假报保存成功；回读和重试不破坏一致性 |
| A10 | 会话/草稿回读、作品切换与关窗 | 历史及候选关联正确；不串书、不自动重放写入；运行时关窗先确认、停止并完成必要保存；彻底退出重开后不自动续跑 |
| A11 | 只讨论或审稿，或只要求写一章 | 不把讨论当写入授权，不自动追加下一章 |
| A12 | 使用原 Agent、妙笔、续写及编辑器 | 本次改动不破坏原有行为、数据与模型选择；依据改动影响范围完成回归 |

验证分层记录：

- 契约、状态、存储与失败注入测试用于检查确定性规则；模型自称“保存成功”不作为数据库验收证据。
- 真实 Pi + 模拟模型用于稳定重现事件、工具、停止和故障，不能代替真实供应商兼容性验证。
- 真实桌面与 SQLite 验证覆盖平台实际写入、页面生命周期和恢复；IndexedDB测试或浏览器模拟不能替代这一层。
- 真实模型使用明确的模型版本、配置、测试作品和输入，记录工具行为与创作结果。写作质量单独由作者评估，不以一篇成功样稿证明稳定性。
- 验收前确认测试平台与真实模型配置；未经测试的 Windows/Linux 或供应商明确标为未验证。暂不打包发布的限制保持有效。

技术疑点可在设计阶段做有明确问题和成功标准的小实验；实验结果回到设计记录，不能替代需求确认或整体验收。
