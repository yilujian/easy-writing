# 工作流建书：报错与样式修复记录（2026-10-31）

备份：`../easy-writing-workflow-backup-20261031-2235/`（改前的 `workflow-generation.ts`、测试、引擎、两个提示组件、整个 `views/WorkflowBook`）。

## 一、经常报错的原因（按本机记录核对）

大纲和设定生成原来分两段：先让模型出一份"任务清单"（每块的类型、名称、说明），再逐块生成。第一段经常失败：

- 10-31 22:26 第一次清单返回 531 字，缺字段被拒（"任务清单缺少类型、名称或规划说明"）。
- 22:26:54 第二次停在"等待"再没更新，记录卡在"运行中、0 项"，页面上就是那张 0/0 的"大纲恢复草稿"卡，两个按钮灰着。
- 22:28 第三次模型没出清单，直接把整份大纲 JSON 写了出来，被"缺少必要内容"拒掉。10-29 09:33 也是同样先失败一次。

另有几条和模型无关的任务失败："还没有可用模型"两次、"请求失败"三次（网络或代理）、"JSON Parse error: Unexpected EOF"一次（空响应）。

## 二、改法

1. **不再让模型出任务清单。** 每一步要生成哪几块由平台定死：大纲三块（总纲、分卷规划、开篇章纲），设定四块（世界背景卡、核心体系、人物、故事线）；调整时按范围取对应的块，只改一个人物或故事线时只生成那一条。逐块生成、逐块落盘，哪块失败从哪块继续。作者在某块生成前手动加的条目，按条目记，不会被后来生成的整块冲掉。调整时"保留数量"仍强制校验，数量不对就退回。（`src/utils/workflow-generation.ts`、`workflow-generation-document.ts`）
2. **卡在"运行中"的记录在读取时修正。** 没有任务在跑却写着运行中的：有过清单的改成"未完成"，作者可以继续或放弃；什么都没生成的直接作废。（`listRecoverableGenerations`）
3. **单章字数失控。** 原来细纲固定 5 到 8 拍，模型按拍子展开，3000 字的章常写到五六千；正文提示词里的"写满剧情"也在往长里推。现在拍数跟着目标字数走（每拍约 600 字，3 到 8 拍；3000 字 → 5 拍），正文提示词给硬上限（目标的 1.2 倍）并要求写到目标字数附近就收尾、剩下的留给下一章。三段默认提示词改了，旧指纹已登记（`legacy-defaults.ts`），作者没改过的提示词文件会自动升级。
4. **样式。** 表单顶部不再放"正在生成/已等待 N 秒"的进度条和"恢复草稿"卡。生成进度、停在哪一块、手动修改没存上，都收进页脚一行状态文字；"放弃草稿"按钮进页脚，主按钮仍是"继续补全大纲/设定"。报错只保留一处红色面板（带模型、编号、重新生成），不再同时弹 Toast；"继续补全"失败也走同一个面板。`WorkflowGenerationNotice` 组件删除；`WorkflowRecoveryPanel` 只留在调整抽屉和写作台控制面板里。

## 六、真机验证（2026-10-31 23:30 – 11-01 00:40）

用本机配置的工作流模型（DeepSeek V4 Flash）和独立的数据目录跑真实流程：`scripts/verify-workflow-real.mjs` 起中继与隔离应用，`tests/workflow-real.html` 在应用里按作者的操作顺序点页面。真实 API 密钥只在中继进程里，不进测试库。三轮共 23 次真实请求，每次请求的原文、返回与台账都在 `output/workflow-real-20261031/`、`output/workflow-real-20261031-b/`、`output/workflow-real-20261101-c/`。

作者会看到的：

- **灵感、大纲**：一次通过。大纲生成到第二块时取消，页脚显示"大纲生成到一半，已完成 1/3，停在分卷规划"；点"继续补全大纲"只补剩下两块，不重做总纲。结果 3 个书名、3 卷、8 章。
- **设定**：应用被关掉再打开，页脚显示"设定生成到一半，已完成 0/4，停在世界背景卡 / 上次生成在应用关闭或页面刷新时中断"；继续后四块全部完成（6 张世界背景卡、4 项核心体系、人物、5 条故事线）。
- **第一章**：3423 字（目标 3000，上限 3600），5 拍。设定核对员找出 2 高 2 中 1 低共 5 个问题，修订编辑只改了 4 处（去掉"激活条件满足""首次拆解免费"，"第二遍"改"再次"），其余一字未动。
- **报错面板**：供应商拒绝（402）时页面只有一处红色面板，没有 Toast，表单顶部没有恢复卡，页脚"大纲生成到一半，已完成 0/3，停在总纲"，有"放弃草稿"按钮。
- **失败点**：第二章细纲。模型把 endHook 塞进 beats 数组里、外面又重复一份，JSON 不合法，任务停在"生成结果不是完整的有效结构，草稿已保留，可沿用草稿重试"。这是模型输出质量问题，不是平台逻辑问题；第一章已落库，重试会从第二章续写。
- **一个认知修正**：建书任务是整本连续写（本次 8 章，每章 3–4 次请求），不是只写第一章；验证脚本靠请求预算在第 9 次截断。

顺手修的三处：

1. 细纲这一步失败时，任务上记的还是上一章（页面会显示"第 1 章《F级废脉》"出错，实际是第 2 章细纲失败）。改为记在正在准备的这一章。（`local-workflow-writer.ts`，用例"第二章细纲返回非法结构"）
2. 控制台每次请求结束后报 "The resource id N is invalid"（第一轮 3 条、第二轮 7 条）。原因：模型给出完成标记后代码立刻 `reader.cancel()`，和 HTTP 插件正在进行的最后一次读体撞车，Rust 端读到末尾已释放资源。改为先把流读完让连接自然关闭（最多等 1 秒），第三轮 5 次请求控制台 0 条。（`workflow-ai.ts`，两条用例）
3. 模型完整返回但最后一次写盘失败时，草稿没标"完整"，作者重试会再付费请求一次而不是沿用草稿。把"完整"标记提前到内容校验通过之后。这是原有测试里的隐患，被上一条改动的时序变化暴露出来。

没做、待作者定：

- 细纲、核对这类小的结构化请求返回非法 JSON 时，要不要自动重试一次（每次约 1500 token），或对支持的供应商打开 JSON 模式（`response_format`）？目前只能作者手动点重试。
- 建书任务开始前没有"整本大约多少次请求"的估算和确认，点了就一路写到底。
- 设定里的人物背景与大纲章纲有冲突（人物说系统在觉醒仪式上触发，章纲说当晚才出现），核对员按人物资料改了正文。设定是按大纲生成的，生成时是否应以章纲为准，需要定。
- "请求失败"、空响应这两类网络层错误仍没有样本。
