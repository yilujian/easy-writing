## 常用词库实现与样式

状态：2026-10-08 本地完成，尚未提交发布。

- 自定义词条保存在既有作品参考资料的 `commonWords` 中，角色姓名、别名和设定名称从原资料派生。沿用现有资料导入导出，不增加独立备份流程。
- 正文按 macOS `⌘⇧L` / Windows `Ctrl+Shift+L` 打开取词弹窗，支持文字、拼音、首字母搜索，方向键选择、Enter 插入、Esc 关闭。插入为普通正文编辑，可单步撤销，不计为 AI 生成，也不触发 AI 自动补全。
- 普通写作与工作流共用词库管理组件；顶部新增按钮展开表单，词条显示来源与别名所属角色，修改和删除动作在悬停或键盘聚焦时显示。
- 按确认的设计稿调整搜索、列表、键帽、取词弹窗与工具栏图标；颜色使用既有主题变量，适配无界通透、古韵信笺、森系护眼、暗夜水墨。暗色强调文字单独提高对比度。
- `pnpm check`：346 项测试通过、1 项跳过；类型检查、Lint、生产构建通过。浏览器使用独立测试作品验证新增、编辑展开/取消、搜索、键盘插入和撤销，1440×1000 与 1100×800 无面板横向溢出。视觉证据见 `design-qa.md`。
- 本次样式验收使用浏览器，没有构建或运行原生桌面安装包。
- 2026-10-09 追加 Windows 验收：旧版角色进入词库、失败后新增词条、迁移与备份恢复后的词条保留，以及 Ctrl+Shift+L、搜索、Enter 插入和 Ctrl+Z 撤销通过。环境为 Parallels Windows 11 ARM64 运行 x64 程序，详见 `docs/windows-storage-verification.md`。

## 榜单抓取修复

状态：2026-10-07 已在主分支修复，尚未提交发布。

- 七猫线上响应确实包含以空白开头的旧式折行响应头。相同接口、相同网络下，使用项目 HTTP 插件的 reqwest 默认配置报 `error sending request for url`，底层为 `client error (SendRequest)` 和 `invalid HTTP header parsed`；开启 HTTP/1 及折行响应头兼容后返回 HTTP 200、20 条榜单数据。此前 curl 成功只能说明接口可访问，不能代表桌面客户端的解析器可读取。
- 已移植 Agent 工作区的 `src-tauri/src/qimao_rank_http.rs`，核心配置为 `http1_only()` 和 `http1_allow_obsolete_multiline_headers_in_responses(true)`；`src/utils/local-rank-qimao.ts` 对接 IPC，继续复用既有榜单解析及分页。兼容范围限定到七猫公开榜单接口，未合并其他 Agent 功能。
- 请求结束或取消后释放原生资源；Tauri 返回的字符串错误统一转为 Error，界面保留具体失败原因。
- 番茄首次加载来源，以及切换榜单类型时，都会将分类重置为“全部”。“全部”是已抓取数据的汇总视图，抓取按钮没有单一目标而被禁用；页面虽有提示，但缺少可操作的引导。
- 根据作者调整，已移除分类选择浮层。番茄未选择具体分类时，点击“抓取全部分类”弹出确认框，明确当前男/女频、榜单类型、分类数量和“耗时较长”；确认后依次抓取这些分类，取消不发出请求。“全部”浏览视图保持不变，选中具体分类时仍直接抓取单个分类。
- 批量抓取沿用既有快照与半小时缓存规则，不新增任务或备份存储。界面显示当前进度，结束后分别汇总更新、使用已有数据及失败分类；单项失败不影响后续分类。抓取间保留请求间隔，避免并发请求整批分类。
- 抓取期间不能重复启动；点击现有“关闭”或离开页面后，当前分类结束即停止后续分类。顶部控件在窄窗口中换行，平台名称保持完整。

## 角色别名实现

状态：本地已实现，尚未提交发布。同一角色的多个称呼共享身份、资料和 AI 上下文。

### 数据与保存

- 在既有 `Character` 增加 `aliases: string[]` 的业务语义；旧记录允许缺少字段，读取时按空数组处理。示例：`name: '苏平', aliases: ['小苏', '苏大人']`。
- 身份仍由 `bookId + character.id` 确定。姓名及别名都只是可修改的称呼，不作为角色主键，不创建重复角色。
- 别名随现有作品参考资料保存，通过既有角色读写服务操作；不增加独立正文、别名文件或另一套持久化主数据。匹配索引按需从角色资料生成。
- 同一角色内去除首尾空白、空项、重复项及与正式姓名完全相同的项；不按空格拆词、不擅自改写称呼。
- 新增、修改、删除别名，以及角色改名，都要走同一套规范化逻辑。普通角色面板、工作流角色面板和导入路径保持一致。

### 编辑与匹配

- 在角色姓名下增加“别名”输入，使用可添加和删除的标签；支持多个称呼，保留现有页面布局。
- 搜索正式姓名或任一别名都返回同一个角色。正文出现别名时，高亮和悬浮资料仍展示正式姓名与同一份角色信息。
- 共享称呼索引返回全部候选角色，供搜索、正文匹配和 AI 上下文共同使用，避免各入口维护不同规则。
- 同名或同别名按作品判断。允许不同角色使用“王爷”等相同称呼，但录入时提示冲突；命中后展示候选，不按第一条记录自动认定身份。别名与其他角色正式姓名重名，也按歧义处理。
- 重叠称呼优先匹配较长文本，按字面量处理正则特殊字符。高亮开关和忽略规则只影响展示，不影响 AI 的角色资料来源。
- 增删别名只更新资料和匹配结果，不自动替换既有正文，也不更改人物关系、时间线或剧情绑定的角色 ID。

### AI 使用

- 增加共享角色上下文组装入口：根据作品、用户输入及实际引用的正文，以姓名和别名查找角色，再按角色 ID 去重，读取同一份最新角色资料。
- 向模型提供明确的对应关系，例如“苏平；别名：小苏、苏大人；以下资料均属于同一角色”，并附带相关角色设定。
- 同一称呼匹配多个角色时，把歧义与候选明确传入，不能把多个角色资料合并或假定同一人；缺少依据时保留不确定性，需要时向作者澄清。
- 覆盖与此需求直接相关的妙笔对话、AI 补全/续写、工作流正文生成。不同入口共用角色称呼和上下文规则，而非复制多套拼接代码。
- 妙笔与补全在请求前读取本作品最新角色资料；工作流章纲、细纲及正文生成也改读正式角色库，不再只使用建书时的角色摘要。
- 正式作品以角色参考库中的别名为准；尚未创建作品的工作流设定允许携带别名，建书时映射到正式角色记录，后续请求不可继续用旧设定覆盖作者修改。
- 相关角色上下文需要控制大小；优先保留已命中角色的姓名和别名对应关系，再处理长背景描述。发送上下文能改善模型识别，不能保证所有模型每次判断正确。

### 兼容与备份

沿用现有整包保存和导出恢复，本项未修改备份实现，未新增备份文件、数据表、任务或恢复流程。

- 旧作品及旧备份缺少别名时正常打开。新增字段保存在现有角色 JSON 中，无需单独增加别名 SQL 表。
- 目录参考资料备份、全量 ZIP 备份、覆盖恢复和合并恢复都保留别名。恢复时重映射角色 ID，别名继续跟随对应角色，不按姓名跨书合并。
- 工作流角色类型、表单映射、设定解析和建书导入需要透传别名，避免在中间转换时丢失。

### 完成条件

- 别名新增、修改和删除后，切换角色、关闭面板及重启仍正确；保存失败明确提示，不显示已成功。
- 搜索姓名和别名找到同一角色；正文命中别名展示正确资料；同名冲突列出候选，长短称呼重叠不误取短称呼。
- 妙笔、补全及工作流生成的实际请求消息包含正确的别名映射；多次提到同一角色不重复塞入资料，重名角色不混合。
- 旧数据兼容；新备份覆盖恢复与合并恢复后，别名、角色关系及剧情绑定保持正确。
- 普通模式与工作流模式一致；作者修改既有作品别名后，AI 请求读取更新后的值。
- 使用具体模型验证别名识别效果，并将模型效果与上述确定性数据验收分开记录。
